# 月报 Skill 生成器（Monthly Report Skill Builder）v3.3

> **定位**：生成器不是"问卷模板机"，你（agent）不是"问卷填写员"。**你是有判断力的智能体**，和用户一样懂"千人千面"——每个项目的月报长什么样、哪里会翻车，**由你分析、你判断**，而不是被一份写死的问卷束缚。
>
> 生成器给你两样东西：
> 1. **一条启动命令**（下面「启动命令」节）——用户把它交给任何 agent，就能开始定制。
> 2. **一套引导协议**（下面各节）——告诉你怎么走完整个过程，**以及什么时候该用什么方式和用户交互**。
>
> 参考素材：多个已自动化项目的经验矩阵 + 复杂样本。难点与陷阱的完整清单在 `references/difficulty-checklist.md`——那是**你的自检清单**，不是给用户看的问卷。
>
> **v3.3 新增两条硬规则**（来自真实 agent 实测教训）：
> - **「能解析的绝不问」是硬判据，不是建议**：见「0.5 可执行判据」。产出的问卷/问题里出现可解析却问的项 = 你没分析到位，先回去解析再交互。
> - **产出 Skill 的执行层防御必须内置**：见「3. 收尾」。表格行增删走 XML 层、合并感知、清 run、绝对路径+重试，不能等用户踩坑。

## 启动命令（用户把它交给 agent）

> 把下面这段（连同本 Skill 的 `references/difficulty-checklist.md`）作为对 agent 的提示。变量按实际填：

```
帮我用 monthly-report-skill-builder 把「{项目名}」的小红书/公众号/…月报固化成每月可自动执行的 Skill。

先做环境检查（check_env.py），然后 dump 模板结构（dump_shapes.py <模板路径>），
自己分析这个项目的复杂度：哪些页会翻车、数据从哪来、表格怎么更新、截图怎么换、AI 文案怎么写。
分析过程中需要我决策的地方，随时问我；问题成批或较复杂时，用一份排版良好的 .md 文档
一次性收集，我会勾选/填空。一轮没问完没关系，后续还有问题继续问。

最后产出一个独立的项目专属 Skill（SKILL.md + scripts/ + references/），
放在我自己的 skills 目录，每月我自己跑，不需要上传或帮别人生成。
```

## 引导协议

### 0. 你的角色：自主引导者，不是问卷调查员

- **你来分析，你来判断。** 模板解析、复杂度判断、翻车点预判，都是你的工作——`dump_shapes.py` 解析 Shape/表格/截图结构，你据此想清楚这个项目会踩哪些坑。
- **用户只需要做「人才能做的决策」**：数据源来源与路径、表格更新规则、截图提供方式、AI 文案风格、KPI 口径等。能由脚本解析、能由你判断的，绝不让用户回答。
- **格式陷阱你自己做**：行距模式（LineRuleWithin）、字体字号、Type=14、字符级数字格式——这些用户通常答不上来，你用 COM 探测（`format_audit` 思路），探测结果写进产出 Skill 的 `format-notes.md`，不要拿去问用户。

### 0.5 可执行判据：必问 / 必不问 / 必预填（v3.3 硬规则）

真实 agent 实测教训：即便协议写了「引导式、无问卷」，agent 仍可能退化成甩固定问卷（把能解析的也拿去问用户）。**这一节给死规矩，发任何问题/问卷前必须过一遍。**

**必不问——你自己解析/判断，绝不能拿去问用户：**
- Shape 名/类型/坐标/页面数/标题、表格行列数、截图嵌法、重名清单 → `dump_shapes.py` 就有
- 数字格式（千分位 / ¥ / 百分比小数位 / 全角逗号）→ 从模板文本直接 parse
- 表格结构、列名、每列含义 → 打开表格单元格读
- 项目名/平台 → 从模板标题/项目路径读
- 图表是静态截图还是程序生成 → 看模板里有没有原生图表
- 图片/图标是不是装饰（如 KPI 卡旁的 Group）→ 看位置和类型，不用换就不问

**必问——只有用户知道，问的时候预填你能解析的：**
- **数据源**（最核心）：每个后台/文件从哪来、放哪、每月怎么更新
- 数据窗口规则（如「上月3号~本月2号」）、月报每月几号做
- **页面是否动态**：数据多时会不会多一页 / 复制页（如「广告多投一次就多一页」）
- 截图谁截、放哪、命名约定
- 累积数据（跨月累加值）从哪来：后台全量 vs Skill 自维护历史
- 笔记数 / 投流笔记数 的浮动范围（超了怎么处理）
- AI 文案：哪些段每月重写、风格、喂什么数据

**必预填：**
- 一切你能解析的结果标 ✅，用户只核对。
- 未知项宁可留空让用户填，**不要瞎猜、不要编**。

**自检（发问卷/问题前必须过）**：
- 问卷里有没有「能解析却问」的项？有 → 删掉，回去解析。
- 有没有让用户「描述表格结构 / 描述 shape / 描述图片内容」？有 → 这是你的活。
- 问的是不是都是「只有用户才知道」的？不是 → 重新整理。

### 1. 什么时候、用什么方式和用户交互

没有固定的问卷模板。**交互形式由你按当下情况决定**：

| 情况 | 建议方式 |
|------|---------|
| 一两个小问题 | **直接聊天问**，不用建文件。 |
| 成批决策点（数据源清单、逐页更新规则等） | 用一份**排版良好的 `.md` 文档**收集：☑/☐ 选项 + `【填写】` 行，一次给用户勾选填空。 |
| 需要用户确认解析结果（重名 Shape、表格结构等） | 在文档里**预填 ✅**，用户只核对 + 填决策点。 |
| 一轮之后又有新问题 | **继续问、继续交互**——不要以为一份文档就够。每次补充的问题可以单独问，也可以开新文档，灵活处理。 |

**核心原则**：
- **能解析的绝不问**：Shape 名、类型、表格行列、文本、页面数、标题、重名清单——你跑脚本预填并标 ✅，用户只核对。
- **只问人才能做的决策**：上面 0 节列的那几类。拿不准该不该问就**先问**，宁可多确认一次。
- **用文档时**：开头一句话说明"我已解析模板，预填的标 ✅，你只需确认 + 填带【填写】的"，结尾一句"填完保存告诉我"。**文档内容按项目实际来**——这一页没有表格就不问表格，别套全量。
- **别一次把所有问题甩完**：跟着分析节奏走。先解决这一批，再解决下一批。

### 2. 你应该自己排查的维度（自检清单）

分析每个项目时，自己过一遍这些维度（详细对照 `references/difficulty-checklist.md`），**按项目实际挑相关的深挖**，不要机械照搬：

- **环境与前提**：Windows、PowerPoint COM、模板存在、历史月报存在。
- **页面级**：每页类型；页面是否动态（数据多时复制页 → 定位不能靠页码）。
- **Shape 定位**：重名 Shape（跨页同名、页内同名）→ 名字只作参考，定位靠坐标/顺序/类型+索引；重复标题多页 → nth「第 N 次匹配」。**产出 Skill 必须含每页 Shape 定位策略表（shape-map.md）**。
- **表格**：更新模式五选一（单列固定/整表覆写/滚动窗口/动态行/动态列）；时间方向（月作行/列）；动态行规则（行数变化、样式复制来源、空行）；动态列规则（每月追加、新列样式）；表内固定汇总行（数据行插在哪）；伪合并表头；Type=14 路径；只展示不更新的表格。
- **截图/图表**：逐槽位嵌法（独立图片/占位符内嵌 blipFill/Group，同页可混合）；命名约定；要不要 OCR（提取后填到哪个 Shape）；替换方式；图表是静态截图还是 matplotlib 生成。
- **数据管线**：多数据源映射（逐源问清供哪些页/表/列）；数字清洗（全角标点归一、缺千分位补全、去空格）；**数据月份 vs 报告月份校验**；累积 KPI 跨月持久化；AI 文案两阶段（摘要→prompt→文案）。
- **AI 文案**：哪些段落每月重写；每段开头惯例（前缀词/段落数/是否含归因分析）；喂什么数据上下文。
- **KPI 形态**：月度目标 vs 合同累积目标。

### 3. 收尾：读答案 → 产出 Skill

1. 用户填完/回答完 → 你整理进 `answers.md`（结构化记录，供生成 Skill 时对照）。
2. 有模糊处就补问，尽量一轮收敛，但**不为此硬凑**——信息不齐宁可再问。
3. 信息够了 → 产出项目专属 Skill 目录，放进用户自己的 skills 目录：

```
skills/{project}-{platform}-report/
├── SKILL.md                  ← 每月执行手册：环境检测→取数据→prep→AI文案→应用→审计→输出
├── scripts/
│   ├── check_env.py          ← 环境检测（强制内置，第一步必跑）
│   ├── data_prep.py          ← 数据源→data.json（含数字清洗/月份校验）
│   ├── ppt_apply.py          ← data.json→COM 填模板→输出PPT
│   └── dump_shapes.py        ← 诊断用副本
└── references/
    ├── format-notes.md       ← 格式审计结果（你探测的）
    ├── shape-map.md          ← ★每页 Shape 定位策略表（必备资产）
    ├── data-mapping.md       ← data.json 字段↔表格/槽位映射
    └── data-cleaning.md      ← 数字清洗 + 月份校验规则
```

**ppt_apply.py 必须内置的执行层防御（v3.3，来自真实开发踩坑）**：
- **表格行增删走 XML 层**：`Rows.Paste` 不可靠会直接失败或丢样式；XML 层直接操作表格行，样式 100% 保留。
- **动态行增删按 rowSpan/合并感知处理**：表有纵向合并单元格时，增删行先处理合并结构，不破坏 rowSpan。
- **改 Shape 文本清空多余 run**：只写第一个 run，防止旧 run 残留拼出「4月占比月占比」这类叠加文本。
- **COM 强制绝对路径** + **内置 3 次重试**：相对路径会报错；PowerPoint 残留进程导致 COM 失败时重试能救回来。
- 打开/关闭文件用 try/finally，确保 Quit 不泄漏进程。

**SKILL.md 必须包含**：
- 第一步环境检测（check_env.py），不通过给修复指引。
- 每月执行步骤（数据从哪拿→prep→文案→apply→审计→输出到哪）。
- **每页 Shape 定位策略表**（`references/shape-map.md`）——几乎所有模板都有重名 Shape，这张表是安全运行的前提。
- 本项目专属陷阱（动态表格/动态列/重名 Shape/伪表头/行距模式/月份校验/全角数字/汇总行…）直接写进去。
- 数据校验清单 + 上月数据回退规则 + 数据月份匹配校验。

**验收（冒烟测试）**：用**上月真实数据**跑一遍产出 Skill，能出 PPT 才算通过。通过后 Skill 留在用户自己机器上，**下个月开始**每月自跑：放数据 → 跑一条命令 → 出月报。无需上传，无需给别人生成。

## 陷阱自检总清单（参考）

完整对照见 `references/difficulty-checklist.md`。核心条目（自己逐条过，按项目挑相关的问）：
1. 环境未检就硬跑
2. Shape 名重名还按名找
3. 动态表格按固定行列写死
4. **动态列（月份作列每月追加）当固定列处理**
5. 伪合并表头当真合并处理
6. 占位符内嵌截图按独立图片替换
7. 同页多种截图嵌法却整页一刀切
8. 重复标题多页不用 nth 定位
9. 动态表有固定汇总行还从表头往下插数据
10. 行距模式判断错
11. Type=14 走标准路径
12. 多数据源映射对不上
13. 数据月份与报告月份不匹配照填
14. 脏数字（全角标点/缺千分位）不清洗直接入库
15. AI 文案直接塞进数字管线
16. 产出 Skill 不带环境检测、定位策略表和冒烟测试
17. 动态页面溢出复制还按页码定位
18. 截图上的字要 OCR 提取却漏了
19. KPI 是合同累积目标却当月度目标
20. 只展示不处理的表格还去填数
21. **把用户当问卷机器，让用户回答你能解析/能判断的东西**
22. **产出固定问卷模板（Part A–E 大问卷）而非引导交互**——即便协议写着无问卷，也容易退化成甩一份完整问卷 → 发前过 0.5 判据自检
23. **产出 Skill 没内置执行层防御**（XML 表格行增删 / rowSpan 合并感知 / 清多余 run / 绝对路径 + 重试）→ 见 3. 收尾
24. 让用户「描述表格结构 / 描述 shape / 描述图片内容」——那是你的活
